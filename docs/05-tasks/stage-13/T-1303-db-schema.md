## Итог
- **drizzle-kit не используется:** он тянет устаревший esbuild с 4 moderate-уязвимостями, а в проекте было 0. Вместо него — свой мигратор (`server/src/db/migrate.ts`, ~40 строк): файлы `NNNN_name.sql` по порядку, каждый в транзакции, учёт в `schema_migrations`, при ошибке — откат и имя файла в сообщении. Drizzle (`drizzle-orm`) — только для запросов; соответствие схемы и SQL проверяет тест, который пишет и читает каждый столбец.
- E-mail уникален без учёта регистра (`unique index on lower(email)`), без расширения citext. Удаление пользователя каскадно удаляет сессии и токены (удаление аккаунта в ТЗ — сразу и полностью, поэтому `deleted_at` не нужен).
- Базы: `DATABASE_URL` → PostgreSQL (пул `pg`, миграции на одном соединении); без него — PGlite: в разработке файлы в `server/.data/pglite` (в `.gitignore`), в тестах — в памяти. В production `DATABASE_URL` обязателен.
- Сервер применяет миграции при старте; отдельно — `npm run db:migrate`. Проверено запуском: первый старт применил `0001_auth.sql`, второй — без изменений.
