# Модель ученика

> Этап 19. Научная основа — [ROADMAP.md](../ROADMAP.md), раздел 5. Вся логика — чистые функции в `src/lib/learner/`, данные — в уже существующем прогрессе и сделках тренажёра. Сервер не нужен: модель считается в браузере и синхронизируется вместе с прогрессом.

## 1. Зачем
Сейчас сайт знает, какие уроки прочитаны и какие тесты сданы. Он не знает, что ученик понял, что забыл и что знает на словах, но нарушает в сделках. Модель ученика отвечает на три вопроса:
1. **Что я знаю?** Оценка знания `K` по каждому навыку из ответов в тестах.
2. **Что я делаю?** Оценка поведения `B` по сделкам тренажёра для навыков, у которых есть проверяемое правило.
3. **Что делать дальше?** Повторение, теория или практика в зависимости от того, чего не хватает.

## 2. Граф навыков
- Около 30 навыков (`src/content/skills.ts`), у каждого: `id`, название, группа, теги вопросов, уроки, навыки-предпосылки.
- **Вопрос относится к навыку**, если хотя бы один его тег входит в теги навыка. У вопроса может быть несколько навыков.
- Теги вопросов — это id терминов глоссария, поэтому термины навыка получаются из его тегов без отдельной разметки.
- Предпосылки образуют граф без циклов. Рекомендация не предлагает навык, пока предпосылки не освоены хотя бы на `K ≥ 0,6`.
- Проверка контента: каждый вопрос каждого теста относится хотя бы к одному навыку, у каждого навыка есть вопросы и уроки, уроки навыка существуют и проверяют его теги.

## 3. Журнал событий
- Попытка теста (`QuizAttempt`) дополнительно хранит ответы по вопросам: id вопроса, верно или нет, теги, время на вопрос, уверенность (если отмечена).
- Старые попытки без ответов учитываются по сводке «тег → верно/всего»: каждая пара — наблюдение по навыку, теги одного навыка внутри попытки не суммируются, а берётся максимум, чтобы не считать один вопрос дважды.
- Сделки тренажёра уже хранятся в IndexedDB и синхронизируются. Бэктесты стратегии (`strategyTag`) в оценку поведения не входят: там правила задаёт стратегия, а не ученик.
- Отдельного хранилища нет: журнал событий — функция от прогресса и сделок.

## 4. Оценка знания K (BKT)
Байесовское отслеживание знаний (Corbett, Anderson, 1995). Для навыка четыре параметра:

| Параметр | Смысл | По умолчанию |
|---|---|---|
| `pL0` | Знал до первого ответа | 0,2 |
| `pT` | Научился после очередного ответа | 0,15 |
| `pG` | Угадал, не зная | 0,2 (выбор из 4 — 0,25, «верно/неверно» — 0,5, число — 0,05) |
| `pS` | Ошибся, зная | 0,1 |

- Ответы обрабатываются по времени. Угадывание берётся по типу вопроса, если тип известен.
- **Забывание:** между сессиями оценка тянется к `pL0` с периодом полураспада 30 дней. Это нужно для повторений (раздел 7).
- Навык **освоен** при `K ≥ 0,85` и не меньше чем трёх ответах.

## 5. Оценка поведения B
- Правила и их навыки: риск на сделку ≤ 1 % → «Риск на сделку и лимиты»; плановое R:R ≥ 1,5 → «R:R, винрейт и матожидание»; не входить после дневного убытка 3 % → «Просадки и серии убытков»; без сделки из мести → «Эмоции и когнитивные ловушки».
- Размер позиции в тренажёре считается сам по риску, а стоп нельзя поставить не с той стороны, поэтому отдельного правила для них нет.
- Каждая сделка тренажёра даёт по каждому применимому правилу «соблюдено» или «нарушено».
- `B` — среднее Beta-распределения `Beta(1 + w·соблюдено, 1 + w·нарушено)`. Вес сделки `w = 0,5^(возраст / 30 дней)`, поэтому свежие сделки важнее.
- Пороги — из курса. Торговый план пишется свободным текстом, числа из него не извлекаются.
- Сделка из мести: вход в течение 15 минут после убыточной сделки с риском выше, чем в ней. Правило проверяется только у сделок, которым предшествовал убыток в эти 15 минут.
- Правило дневного убытка проверяется только у сделок, перед которыми в тот же день уже был убыток.
- Без сделок `B` не определено, и это видно в интерфейсе: «нет данных», а не 0.

## 6. Разрыв «знаю — делаю»
- `G = K − B` для навыков с правилом.
- Разрыв **значим**, если `P(K − B_beta > δ) ≥ 0,9` при `δ = 0,2` и правило проверено хотя бы в трёх сделках (при равномерном априорном распределении одна нарушенная сделка уже даёт вероятность 0,91), где `B_beta` — распределение из раздела 5. Вероятность считается точно через функцию распределения Beta (без случайности, чтобы тесты были детерминированными).
- Типы дефицита:

| `K` | `B` | Тип | Что предлагаем |
|---|---|---|---|
| < 0,6 | любое | знание | Урок и повторение вопросов навыка |
| ≥ 0,6 | значимо ниже | поведение | Сценарий тренажёра и разбор своих сделок |
| ≥ 0,6 | нет данных | нет практики | Сделка в тренажёре |
| ≥ 0,85 | не ниже | освоен | Ничего, только плановое повторение |

## 7. Интервальные повторения
- Повторение навыка нужно, когда `K` с учётом забывания опустилась ниже 0,7 у навыка, который раньше был освоен, или прошло больше интервала после последнего ответа.
- Интервалы: 1, 3, 7, 14, 30, 60 дней. Верная серия переводит на следующий интервал, ошибка возвращает на первый.
- На главной блок «Сегодня повторить»: до 3 навыков и короткий тест из 5 вопросов их уроков.

## 8. Калибровка уверенности
- В тестах уроков ученик может отметить уверенность: «уверен», «сомневаюсь», «угадываю».
- Уверенный неверный ответ — сигнал заблуждения: такой навык поднимается в рекомендации выше.
- В «Моих навыках» показывается калибровка: доля верных ответов при каждой отметке.

## 9. Интерфейс
- **«Мои навыки»** (`/skills`): группы навыков, у каждого — полоса `K`, отметка `B` (если есть), значок разрыва, ссылки на уроки и сценарии.
- **Следующий шаг** на главной выбирается по модели: сначала значимый разрыв, затем повторение, затем непройденный урок.
- Тексты без процентов-оракулов: «знание — хорошо, на практике — часто нарушается», а точные числа — в подсказке.

## 10. Ограничения
- Модель мерит тренажёр, а не реальную торговлю.
- Параметры BKT заданы, а не обучены. Подбор на данных — этап 28.
- Мало ответов — широкая неопределённость. Интерфейс показывает «мало данных», пока ответов меньше трёх.
