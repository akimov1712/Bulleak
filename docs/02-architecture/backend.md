# Бэкенд

ТЗ и план — [accounts-backend.md](../04-features/accounts-backend.md). Здесь описано то, что уже работает.

## Устройство
| Где | Что |
|---|---|
| `shared/src` | Контракт API: схемы zod, коды ошибок, проверка слабых паролей. Используется и сервером, и сайтом |
| `server/src/app.ts` | Приложение Hono без сетевого слушателя; `main.ts` запускает его, тесты вызывают `app.request` |
| `server/src/config.ts` | Чтение окружения. При неверной конфигурации сервер не стартует и перечисляет все проблемы |
| `server/src/db`, `server/migrations` | Схема Drizzle для запросов и SQL-миграции (источник правды). Миграции применяются при старте |
| `server/src/auth` | Пароли, токены, сессии, письма-токены, лимиты, маршруты |
| `server/src/mail.ts` | Письма: Resend в продакшене, журнал в логе локально и в тестах |

## База данных
Продакшен — PostgreSQL. Локально и в тестах — PGlite (Postgres в WASM): установка не нужна, файлы лежат в `server/.data` (вне git), тесты работают в памяти.

## Запуск
```
npm run dev:server   # API на http://localhost:8787/api/v1
npm run db:migrate   # применить миграции вручную
npm run test -w server
```
Настройки — `server/.env` по образцу `server/.env.example`. Локально файл не обязателен. Без ключа Resend текст письма со ссылкой выводится в лог сервера. В e2e письма пишутся в файл `MAIL_OUTBOX` (в production он запрещён).

## API (`/api/v1`)
| Запрос | Что делает | Ответ |
|---|---|---|
| `POST /auth/register` | Создаёт аккаунт и сессию, отправляет письмо | 201 + сессия; 409 `email_taken`; 400 `weak_password` |
| `POST /auth/login` | Вход | 200 + сессия; 401 `invalid_credentials` |
| `POST /auth/refresh` | Заменяет refresh-токен новым | 200 + сессия; 401 `token_invalid` |
| `POST /auth/logout` | Завершает текущую сессию | 204 |
| `POST /auth/logout-all` | Завершает все сессии (нужен access-токен) | 204 |
| `POST /auth/verify-email` | Подтверждает e-mail по токену из письма | 204; 400 `token_invalid` |
| `POST /auth/resend-verification` | Новое письмо подтверждения (нужен access-токен) | 204 |
| `POST /auth/forgot` | Письмо для сброса пароля | всегда 200, если не превышен лимит |
| `POST /auth/reset` | Новый пароль по токену, завершает все сессии | 204; 400 `token_invalid` |
| `GET /me` | Текущий пользователь | 200; 401 `unauthorized` |

Ошибки всегда имеют вид `{ error: { code, message, fields? } }`; `message` — на русском, для интерфейса.

## Безопасность
- **Пароли:** argon2id (19 МБ, t=2, p=1), минимум 8 символов, проверка на частые пароли. Неверный пароль и несуществующий e-mail дают одинаковый ответ и выполняют одинаковую работу.
- **Access-токен:** JWT HS256 на 15 минут.
- **Refresh-токен:** 256 случайных бит на 30 дней, в БД только SHA-256, заменяется при каждом обновлении. Повторное предъявление старого токена завершает всю цепочку сессий. Поэтому клиент не должен обновлять токен параллельно из двух вкладок, а при потере ответа просит войти снова (T-1401). Завершение сессий и сброс пароля закрывают refresh-токены; уже выданный access-токен доживает свои 15 минут.
- **Доставка refresh-токена:** `REFRESH_TRANSPORT=cookie` (сайт и API на одном домене, лучший вариант) или `body` (без общего домена).
- **Письма:** токены одноразовые, в БД только хэш, подтверждение живёт 24 часа, сброс — 1 час. Ссылки ведут на сайт (`APP_URL`), токен находится в части адреса после `#` и не попадает в логи серверов.
- **Лимиты:** вход 5 за 15 минут на e-mail и адрес (успешный вход обнуляет счётчик) и 30 за 15 минут на адрес, регистрация 5 в час на адрес, сброс 3 в час на e-mail и 20 в час на адрес, повтор письма 3 в час. Ответ — 429 с `Retry-After`. Счётчики в памяти одного процесса, интерфейс `RateLimiter` заменяем.
- **Адрес клиента:** `X-Forwarded-For` учитывается только при `TRUST_PROXY=true`, иначе его можно подделать.
- **Заголовки:** CORS только для `APP_ORIGIN`, HSTS, `nosniff`, CSP `default-src 'none'`.
- **Логи** не содержат паролей и токенов: поля с такими именами заменяются на `[redacted]`.
